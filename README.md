# Where Is...?

这是SJTU-软件工程(CS3331)-2026秋课程作业。

一个使用 **Python、Tkinter 和 SQLite** 开发的本地桌面 GUI。对于新到一个实验室的小朋友，找不到各种东西的是限制其大展身手的一大因素，此工具可以帮助在实验室中查找物品、管理存放位置，并将物品与实验 Protocol 关联。程序无需账号或云服务器。

## 功能

- **位置管理**：建立、修改、删除层级位置，展示完整路径，检查循环关系及受限删除。
- **物品管理**：录入主要名称、中英文名、多个别名、类别、备注和所在位置；支持修改、删除、搜索及类别筛选。
- **Protocol 管理**：新建、编辑、删除和搜索实验步骤，关联所需物品；从物品页面反向查看使用它的 Protocol。
- **自动识别与人工确认**：根据库中已有名称和别名生成候选，显示比较依据、字符相似度、类别和位置；支持人工确认及手动补充。
- **文件导入**：支持 DOCX、DOC、PDF、TXT 和 Markdown，保存本地副本，预览提取文字，并选择替换正文、追加正文或仅保存附件。
- **放大阅读**：独立只读窗口，支持调整字号、滚动、F11 全屏及 Esc 退出全屏，也可打开原始文件副本。
- **本地保存**：SQLite 保存记录；Protocol 的未保存修改会在切换记录或关闭前提醒。右侧编辑区可整体滚动。

## 运行环境

- 已验证环境：Windows、Python 3.9.23、Tk 8.6。
- 使用带 Tkinter 的 Python；其他 Python 版本和操作系统未做全面兼容性验证。
- `pypdf` 用于文字型 PDF 提取。
- 旧版 `.doc` 提取还需要 **Windows 本地 Microsoft Word 和 `pywin32`**。安装 Python 依赖不会安装 Word。

物品、位置、手工 Protocol，以及 DOCX、TXT、Markdown 提取使用 Python 标准库。

## 安装与启动

下载并解压源码，在包含 `main.py` 的文件夹中打开 PowerShell。建议使用独立环境：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

如果已经在所用 Python 环境中安装依赖，也可以直接运行：

```powershell
python main.py
```

可用 `python -m tkinter` 检查所用 Python 是否带有可用的 Tkinter。项目目录需要可写；首次启动会自动创建 `lab_inventory.db`。

## 使用方法

### 1. 建立位置、录入物品

1. 进入“位置管理”，创建根位置，再选择上级位置逐层添加，例如 `实验室 > 存放柜 > 第一层`。
2. 进入“物品管理”，填写主要名称、类别和位置，可补充中英文名、别名和备注，再保存。
3. 别名可用逗号或换行分隔。搜索支持名称、别名、类别、备注和完整位置路径，英文忽略大小写。

### 2. 新建 Protocol、确认所需物品

1. 进入“Protocol 管理”，点击“新建 / 清空”，填写名称和步骤正文。
2. 输入正文后稍等，或点击“重新识别”，查看自动候选。
3. 核对名称、正文依据及实际产品，勾选后点击“确认勾选结果”。遗漏的物品可在“手动补充”中搜索、多选并加入。
4. 在“已确认物品”中核对汇总，最后点击“保存新增”或“保存修改”。**识别、勾选和确认不会直接保存数据库关联。**

识别只从已登记物品中挑选候选，不调用 AI API，也不会自动创建未登记物品。字面包含或局部字符相似度严格超过 60% 的结果会显示；相似、宽松包含和重名候选需要主动核对。相似度不是“物品相同的概率”，相似名称也不代表同一产品。

### 3. 导入文件与阅读

点击“导入 Protocol 文件”，选择文件后在预览窗口核对文字。可替换、追加正文，或只保留附件；完成后仍需保存 Protocol。

- **DOCX / TXT / Markdown**：可直接提取文字。
- **文字型 PDF**：使用 `pypdf` 提取，不需要 OCR。
- **扫描或图片型 PDF**：当前不支持 OCR。可保留原件并打开阅读，不能假定已得到完整正文。
- **旧版 DOC**：需要本地 Word 和 `pywin32`；不可用时可先用 Word 另存为 DOCX。

单个导入文件上限为 20 MB。提取文字不是原排版复刻，图片、公式、复杂表格和编号可能不完整；使用前应核对原件。点击“放大阅读”可查看只读正文，修改正文后需重新打开阅读窗口更新快照。

## 数据与隐私

程序使用以下本地路径：

| 路径 | 内容 |
| --- | --- |
| `lab_inventory.db` | 物品、位置、Protocol 和附件关联记录 |
| `data/protocol_files/` | 已保存的 Protocol 原件副本 |
| `data/.protocol_staging/` | 待保存的导入副本 |

导入文件保留本地副本，原源文件移动后仍可打开已保存副本。删除 Protocol 或移除已保存附件只删除关联，不自动删除磁盘副本，以避免误删；当前不提供自动垃圾清理。

手工备份前请关闭程序，同时复制 `lab_inventory.db` 和整个 `data` 文件夹。不要把真实实验数据、附件、照片、密码或密钥提交到公开仓库。`.gitignore` 已排除数据库、附件目录、缓存和本地依赖；网页上传时仍需主动检查文件清单。

## 项目结构

| 文件 | 职责 |
| --- | --- |
| `main.py` | 初始化数据库、启动 GUI |
| `database.py` | SQLite 表结构、查询与事务 |
| `services.py` | 输入校验、业务规则、物品与 Protocol 关联 |
| `ui.py`、`theme.py` | 主窗口、统一样式及滚动布局 |
| `protocol_ui.py`、`recognition_ui.py` | Protocol 编辑和识别候选交互 |
| `matching.py` | 本地名称匹配、字符相似度及原文位置映射 |
| `file_services.py`、`doc_reader.py` | 文件复制、文字提取及旧版 DOC 读取 |
| `protocol_reader.py` | 放大阅读和导入预览 |
| `dependencies.py`、`requirements.txt` | 可选依赖加载与依赖清单 |

## 已知限制

- 每个物品只关联一个位置。
- 识别依据名称和字符规则，可能误报或漏报，需人工核对。
- 未实现扫描 PDF OCR、实验准备清单、设备与位置自动关联、内置备份恢复。
- 未保存修改提醒针对 Protocol 编辑，不涵盖物品和位置表单。
- 暂无账号、云同步或多人同时编辑的冲突处理；适合本地个人使用和课程演示。
